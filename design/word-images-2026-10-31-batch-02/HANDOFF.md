# N5 단어 이미지 추가 · 두 번째 묶음

2026-10-31. 현재 콘텐츠에 등록된 N5 단어 w016–w030에 맞춰 이미지 15장을 추가했다. 새 단어를 임의로 만들거나 기존 단어 ID를 바꾸지 않았다.

## 확인과 저장 위치

- 누적 이미지 모아보기: http://127.0.0.1:4176/word-images.html
- 신규 원본: `../art-direction-2026-10-29/assets/card-{key}-v1.png`
- 원본·크기·알파·파일 크기·SHA-256·단어 연결: `manifest.json`
- 실제 생성 프롬프트: `prompts.json`
- 현재 250개 단어의 이미지 준비 현황과 다음 대상: `coverage.json`
- 누적 30장 카탈로그: `../art-direction-2026-10-29/image-catalog.json`

기본 제공 `image_gen`을 사용했고 기존 고양이 v2를 스타일 참고로 넣었다. 모두 RGBA PNG이며 실제 투명 알파를 확인했다. 13장은 1448×1086, 전철과 날씨는 1447×1087이다. 크기나 투명도를 후처리하지 않고 원본을 보존했다. 모두 약 4:3 비율이며 표시할 때 `object-fit: contain`을 사용한다.

## 실제 앱 적용

실제 `src/`, `content/`, `public/`는 수정하지 않았다. 이미지 원본과 모아보기, 디자인 시안의 그림 매핑만 추가했다. 디자인 시안의 학습용 샘플 단어 목록 자체는 기존 15개를 유지한다.

이번 15개 단어의 현재 콘텐츠 프롬프트에는 `imageAssetId`가 없고, 해당 이미지 미디어 레코드도 아직 없다. 개발 담당 Claude는 다음을 함께 반영해야 한다.

1. 새 PNG를 배포 미디어 폴더에 복사한다. 제안 경로는 `manifest.json`의 `proposedPublicPath`다. 필요하면 배포 과정에서 투명도를 유지한 WebP로 최적화하되, 원본 PNG는 남긴다.
2. 기존 프롬프트 ID `w016-p1`부터 `w030-p1`을 유지하고 각 프롬프트에 적절한 `imageAssetId`를 연결한다.
3. 해당 수준 파일의 `media` 배열에 이미지 미디어 레코드를 추가한다. `proposedMediaId`는 신규 제안 ID이므로 기존 ID 충돌 여부를 확인한다. 예: 물은 `img-water`.
4. 이미지 미디어 레코드에 `id`, `kind: image`, 실제 배포 `path`, 장면 설명, 프로젝트 생성 출처를 기록한다. 기존 콘텐츠의 provenance 형식을 따른다.
5. 기존 허용 표기·가나·단어 뜻·검수 상태·학습 선택·채점 로직을 바꾸지 않는다. 그림 안에 정답 글자를 덧붙이지 않는다.

친구·선생님·학생, 전철·역, 날씨·비처럼 서로 가까운 단어는 행동·소품·중심 대상을 다르게 표현했다. 이미지로 가능한 표현이 하나로 한정되는 것은 아니므로 기존 허용 답안 설계를 유지한다.

## 진행 현황

현재 등록 단어는 수준별 50개씩 총 250개다. 이번 작업 후 디자인 이미지 준비는 총 30개, 미제작은 220개다. 실제 앱 배포 반영 수와는 별개다.

- N5: 18개 준비 / 32개 미제작
- N4, N3, N2, N1: 각각 3개 준비 / 47개 미제작

후속 제작은 `coverage.json`의 `pending` 순서로 진행하면 된다. 현재 다음 대상은 N5 `w031 名前`이다. 이 파일은 현재 콘텐츠를 읽어 작성한 스냅샷이므로 다음 작업 전에 최신 콘텐츠와 다시 맞춘다.

로컬 미리보기 서버가 꺼졌다면 프로젝트 루트에서 `node design/art-direction-2026-10-29/polished-ui/preview.mjs`로 실행한다.
