# 학습 콘텐츠 원본

단어·문법의 원본 파일입니다. 사람이 고치는 곳은 여기뿐이고, 앱이 읽는 파일(`public/content/`)은 빌드할 때 만들어집니다(저장소에 올리지 않음).

```text
content/<수준>/words.json    단어(words) · 학습 카드(prompts) · 카드가 쓰는 그림/소리(media)
content/<수준>/grammar.json  문법
content/songs.json           노래(곡 제목·가수와 그 노래에서 고른 단어·문법의 id)
public/media/images/         그림 파일 (media.path는 "media/images/<이름>.svg"처럼 public/ 기준)
```

타입은 [src/content/types.ts](../src/content/types.ts)가 기준입니다(`design/content-model.ts`에서 시작해 수준별 파일 형식과 manifest를 더했습니다).

## 확인하는 법

```powershell
npm run content
```

`npm run dev`와 `npm run build`도 먼저 이 검사를 돌리며, 오류가 하나라도 있으면 빌드를 멈춥니다. GitHub에 올렸을 때도 같아서 잘못된 콘텐츠는 배포되지 않습니다.

## 오류로 막는 것

- id: 비었거나, 영문 소문자·숫자·`-` 밖의 글자, 다른 곳에서 이미 쓴 id(수준이 달라도). 같은 그림을 여러 수준에서 쓸 때만 같은 media id·같은 경로가 허용됩니다.
- 수준: 폴더와 파일의 `level`, 각 단어·문법의 `level`이 다름. `curriculumOrder`가 1 이상 정수가 아니거나 겹침.
- 읽기: `kana`에 가나 밖의 글자, 예문 `reading`에 가나·문장부호 밖의 글자, `romaji`가 영문 로마자가 아님.
- 연결: 의미의 `readingIds`가 그 단어의 읽기가 아님. 카드의 `wordId`·`senseId`·`readingId`·`imageAssetId`·`audioAssetId`가 없거나 서로 맞지 않음. 출제 읽기가 `acceptedKanaForms`에 없음. 없는 `relatedGrammarIds`.
- 매체: 경로가 `media/…` 형식이 아니거나 실제 파일이 없음, 종류와 확장자가 다름. **그림 설명에 정답 표기·읽기가 들어감**(문제 화면에서 낭독되므로).
- 출처: `provenance`의 작성자·이용 조건·상태가 없음. `reviewed`인데 `reviewedAt` 날짜가 없음.
- 노래: 곡 제목·가수가 비었거나 같은 노래가 두 번, 없는 단어·문법 id, 한 노래 안에서 겹친 id, 단어도 문법도 없는 노래.

## 주의로만 알리는 것

- 예문에 단어 표기가 그대로 없음(활용형이면 괜찮음)
- 카드가 없는 단어, 어느 카드도 쓰지 않는 매체

## 노래에서 고른 단어·문법 넣기

노래에서 뽑은 단어와 문법은 **수준별 파일에 다른 단어처럼 들어가고**, `content/songs.json`은 어느 노래에서 나왔는지만 기록합니다. 그래서 같은 단어가 단어장·문법·학습 카드에도 그대로 나오고, 사이트의 **노래** 메뉴에서 노래별로 모아 볼 수 있습니다. 한 단어가 여러 노래에 나와도 단어는 하나이고, 노래마다 연결만 됩니다.

**가사는 저장하지 않습니다.** 곡 제목과 가수만 남기고, 예문은 가사 구절이 아니라 새로 지은 문장이어야 합니다(가사를 조금 바꾼 문장도 안 됩니다).

### 넘겨주는 파일 (노래 한 곡에 하나, 예: 그록이 쓴 JSON)

```json
{
  "source": { "song": "곡 제목", "artist": "가수", "extractedBy": "Grok", "extractedAt": "2026-11-24" },
  "words": [
    {
      "written": "空", "kana": "そら", "romaji": "sora",
      "korean": ["하늘"], "partOfSpeech": "명사", "level": "N5",
      "example": { "japanese": "今日は空がきれいです。", "reading": "きょうはそらがきれいです。", "korean": "오늘은 하늘이 예뻐요." }
    }
  ],
  "grammar": [
    {
      "expression": "〜たい", "koreanMeaning": "~하고 싶다", "connection": "동사 ます형 + たい",
      "explanation": "자기가 하고 싶은 일을 말할 때 써요.", "cautions": ["다른 사람의 바람에는 〜たがる를 써요."], "level": "N5",
      "example": { "japanese": "水が飲みたいです。", "reading": "みずがのみたいです。", "korean": "물을 마시고 싶어요." }
    }
  ]
}
```

- 단어는 사전 기본형(가사의 `飛んだ` → `飛ぶ`), `kana`는 가나만, `level`은 N5~N1. `romaji`·`example`·`cautions`는 없어도 됩니다(문법은 예문이 하나 이상 있어야 합니다).
- `korean`은 목록이나 쉼표로 나눈 한 줄 모두 됩니다. 채팅 답처럼 ```json 으로 감싼 파일도 그대로 읽습니다.

### 반영하는 법

```powershell
node tools/import-song.ts imports/곡이름.json --dry-run
```

`--dry-run`은 무엇이 더해질지 보여 주기만 합니다. 괜찮으면 `--dry-run` 없이 다시 실행합니다. 파일을 여러 개 한꺼번에 줄 수도 있습니다.

- **이미 있는 단어**(표기와 읽기가 같음)·**이미 있는 문법**(표현이 같음)은 새로 만들지 않고 노래에 연결만 합니다.
- 새 단어·문법은 다음 id(w251…, g006…)와 그 수준의 다음 학습 순서를 받고, 학습 카드도 함께 만들어집니다. 모두 `draft`(검수 전)입니다.
- 같은 노래(제목·가수가 같음)를 다시 넣으면 새 노래를 만들지 않고 그 노래에 더합니다.
- 결과는 빌드와 똑같은 검사를 거치며, 오류가 하나라도 있으면 **어떤 파일도 바꾸지 않습니다.**
- 그록이 정한 수준과 읽기는 추측이라 틀릴 수 있으니 공개 학습 전에 검수가 필요합니다.
