# 구현 백로그·검수 계획 v0.1

## 현재 결과

1단계는 제품·화면·데이터 계약과 로컬 클릭형 시안을 만드는 단계다. 시안 상태는 페이지 새로고침 시 초기화되며 저장과 실제 음성 처리는 다음 단계에서 구현한다.

## 진행 상황 (2026-10-28)

- **2-1 완료**: React 19 + TypeScript 7 + Vite 8 뼈대, 시안 스타일을 그대로 쓴 공통 화면틀, 해시 경로와 직접 진입, 홈. 나머지 화면은 "만드는 중" 안내 + 시안 링크. 화면 테스트 `tests/e2e/shell.spec.ts`가 PC Chrome·iPhone WebKit(320px 포함)에서 직접 진입·메뉴 이동·제목 초점·없는 주소·가로 스크롤 없음을 확인한다.
- **5-1 일부**: 공개 저장소와 Pages 자동 배포(검사 통과 후 배포), 하위 경로 `/JapaneseWordBook/`에서 직접 진입·그림·스타일 확인. 콘텐츠 매체 경로 검증은 2-2 이후.
- 다음: 2-2 콘텐츠 스키마·검증·수준별 로더.

## 콘텐츠 확대

1. 화면 설계용: 단어 15개(각 수준 3개), 문법 5개(각 수준 1개). 초안 표시.
2. 기능 검증용: 수준별 단어 30~50개, 문법 5~10개. 중복·잘못된 읽기·해설 검수.
3. 공개 학습용: 매일 학습이 가능한 분량으로 단계적 확장. 초기 30일에 새 단어를 하루 10개 제공하려면 해당 수준의 검수된 새 단어 약 300개가 필요하다. 예산과 검수 인력에 맞게 수준별로 준비 상태를 표시한다.
4. 전체 수준의 방대한 콘텐츠 완성은 앱 기능 완성과 별도 작업으로 관리한다. 일부 샘플로 N1~N5 전체 콘텐츠를 완성했다고 표기하지 않는다.

## 실제 앱의 핵심 검수 시나리오

- [ ] 같은 날 새로고침하면 같은 카드 순서·위치로 복원된다.
- [ ] 학습 중 수준·목표 변경이 기존 세션을 바꾸지 않는다.
- [ ] 자정 전후·시간대 변경 시 중복 세션이나 기록 소실이 없다.
- [ ] 새 단어/복습 부족 시 중복 없이 실제 수량을 안내한다.
- [ ] 영문 자판 입력을 히라가나·가타카나 후보로 변환하고 선택/Enter로 답안을 구성한다. nn·촉음·요음·장음과 미완성·잘못된 입력·IME 조합·삭제를 검수한다.
- [ ] 직접 입력 채점에서 가나 동등 비교를 지원하되 촉음·장음을 무시하지 않는다.
- [ ] 답 확인·힌트·재시도로 정답률이 부풀려지지 않는다.
- [ ] 마이크 거부·무음·네트워크 실패가 오답으로 저장되지 않는다.
- [ ] 두 번 클릭·두 탭 동시 학습에서 카드 완료가 중복 집계되지 않는다.
- [ ] 저장 실패 시 계속 저장된 것처럼 안내하지 않는다.
- [ ] 즐겨찾기 변경 후 재접속하면 동일한 목록을 볼 수 있다.
- [ ] 잘못된 백업 가져오기가 기존 기록을 지우지 않는다.
- [ ] 콘텐츠 버전 변경 중에도 기존 세션을 완료할 수 있다.
- [ ] PC Chrome/Edge, Android Chrome, iPhone Safari에서 핵심 학습 흐름을 점검한다.
- [ ] 음성 지원은 API 존재뿐 아니라 실제 일본어 인식/재생까지 확인한다.
- [ ] 키보드·200% 확대·320px 화면·모션 감소·일본어 스크린리더 표시를 확인한다.
- [ ] 원격 저장소 하위 경로에서 이미지·검색·직접 진입이 작동한다.

위 항목은 앞으로 실제 기능을 구현하면서 수행할 검수 기준이며 현재 시안에서 통과했다는 뜻이 아니다. 별도 QA 기록에는 이번 단계에서 실제 확인한 것만 적는다.

## 구현 전에 다시 질문하지 않고 진행 가능한 기본값

제품명은 가칭, N5·15장 기본값, 녹음 기본 미저장, 최초 배포는 기기별 저장, 오늘 세션은 시작 시 고정한다. 로그인/유료 음성 API/대규모 콘텐츠 수급은 범위와 비용이 확정될 때 별도로 결정한다.
