# 구현 백로그·검수 계획 v0.1

## 현재 결과

1단계는 제품·화면·데이터 계약과 로컬 클릭형 시안을 만드는 단계다. 시안 상태는 페이지 새로고침 시 초기화되며 저장과 실제 음성 처리는 다음 단계에서 구현한다.

  - 구분: 마이크 거부·없음 → 안내 + 직접 입력 열기(기록 없음), 소리 없음·연결 실패 → 안내 + `unrecognized` 답변 기록(오답 아님, 카드 그대로), 취소 → 기록 없음, 지원 안 됨 → 안내 + 직접 입력.
  - 처음 답의 방식과 글자를 평가에 함께 저장해서, 정답 면이 새로고침 후에도 "들은 말 · 猫"/"내가 입력한 답"을 보여 준다.
  - 화면 테스트는 대본대로 답하는 가짜 인식기로 각 경우를 확인한다. **실제 마이크·브라우저 인식은 아직 확인하지 않았다**(5-2). Chrome의 인식은 인터넷이 필요하고, iPhone Safari·Firefox는 지원 여부가 달라 실제 기기에서 확인해야 한다.
- **4-3 완료**: 다른 방법으로 연습하기(학습 화면 아래, 오늘의 학습 전·후 모두).
  - 듣고 맞히기: 그림·글자 없이 소리만 들려주고 한국어 뜻을 고른다. 보기는 같은 수준의 다른 뜻에서 최대 4개, 뜻이 같은 보기는 빼서 두 개가 동시에 정답일 수 없다. 보기 순서는 세션에 고정되어 새로고침해도 같다. 고르면 바로 정답 면으로 넘어가고 "내가 고른 뜻"을 보여 준다.
  - 따라 말하기: 그림·표기·읽기·뜻과 발음을 보여 주고 "따라 말하기"로 말해 본다. 정답 단어로 들렸는지만 알려 주고, 시도는 답변 기록으로만 남는다.
  - 둘 다 연습 세션(`practice`, 카드 mode `listening`/`repeat`)이라 오늘의 결과·정답률·복습 일정에 들어가지 않는다. 지금 수준에서 학습 순서대로 최대 10장. 끝나면 "듣고 맞히기 연습을 마쳤어요. 3장 중 1장을 바로 맞혔어요."처럼 짧게 알려 준다.
  - 연습에서 틀리면 "다시 연습할 단어로 기록했어요" 대신 "아쉬워요. 정답을 확인해 보세요."(일정에 기록하지 않으므로). 옆 안내도 모드에 맞게 바꿨다.
- **5-2 준비**: 앱에 "이 기기 확인" 화면(`#/check`, 설정 맨 아래 링크)을 넣었다. 브라우저·화면, 기록 저장·보호·사용 공간, 음성 합성과 일본어 음성 목록·사용할 음성, 음성 인식·마이크 권한, 콘텐츠 버전을 보여 주고, "소리 시험 · ねこ"와 "말하기 시험"을 직접 해 본 뒤 결과를 글로 복사한다. 기록은 바꾸지 않는다. 사람이 확인할 목록은 `docs/07-device-check.md`(PC Chrome·Edge, Android Chrome, iPhone Safari).
- **단어 확대(2026-10-31)**: 수준별 50개, 모두 250개(새 단어 235개, w016~w250). 단어마다 읽기·로마자·뜻·품사·예문(원문·읽기·번역)을 넣었고 모두 draft다. 예문 읽기가 원문의 가나와 순서대로 맞는지, 단어 읽기가 예문 읽기에 들어 있는지 따로 확인했다.
  - 그림 없는 카드: `imageAssetId`를 선택 항목으로 바꿨다. 그림이 없으면 한자 표기를 보여 주고 읽기를 묻는 **읽기 카드**, 가나로만 쓰는 단어는 한국어 뜻을 보여 주는 **뜻 카드**가 된다(`src/study/cardFront.ts`). 읽기 카드는 한자가 화면에 보이므로 직접 입력은 가나만 정답으로 받는다(말하기는 인식기가 한자로 돌려주므로 한자도 인정).
  - 기존 화면 테스트는 수준별 첫 3개 단어만 보이게 하는 공용 설정(`tests/e2e/test.ts`)으로 그대로 두고, 전체 목록은 `full-content.spec.ts`가 확인한다.
- **그림 12장 교체(2026-10-31)**: 코덱스 전달서(`design/word-images-2026-10-31/HANDOFF.md`)대로 N4~N1 처음 3개 단어(w004~w015)의 SVG를 새 2D 그림으로 바꿨다. 730×548 WebP(31~66KB, 투명 유지), id 그대로, 설명은 전달서의 장면 설명. 전달서 manifest에 남아 있던 PC 사용자 폴더 경로는 `<사용자 PC>`로 가렸다.
- **N5 그림 30장 추가(2026-10-31)**: 코덱스 묶음 02·03(`design/word-images-2026-10-31-batch-02`, `-03`)의 N5 w016~w045 그림을 연결했다. 새 미디어 레코드 `img-{key}`를 만들고 카드의 `imageAssetId`를 채웠다(id·정답·채점 그대로). 이제 그림 카드는 N5 33개(시안 3 + 새 30) + 다른 수준 각 3개, 모두 45개다.
  - 그림만으로 뜻이 갈릴 수 있는 5개(名前, 今日, 明日, 行く, 来る)는 카드의 `situationHint`에 짧은 상황 설명을 넣어 그림 아래에 보여 준다(예: 明日 "달력에서 표시된 날의 다음 날이에요."). 검증기는 힌트에 정답 표기·읽기가 들어가면 막는다.
  - 묶음 폴더의 manifest·results에 남아 있던 PC 사용자 폴더 경로는 커밋 전에 `<사용자 PC>`로 가렸다. 묶음 04는 아직 만드는 중이라 손대지 않았다.

## 콘텐츠 확대

1. 화면 설계용: 단어 15개(각 수준 3개), 문법 5개(각 수준 1개). 초안 표시.
2. 기능 검증용: 수준별 단어 30~50개, 문법 5~10개. 중복·잘못된 읽기·해설 검수.
3. 공개 학습용: 매일 학습이 가능한 분량으로 단계적 확장. 초기 30일에 새 단어를 하루 10개 제공하려면 해당 수준의 검수된 새 단어 약 300개가 필요하다. 예산과 검수 인력에 맞게 수준별로 준비 상태를 표시한다.
4. 전체 수준의 방대한 콘텐츠 완성은 앱 기능 완성과 별도 작업으로 관리한다. 일부 샘플로 N1~N5 전체 콘텐츠를 완성했다고 표기하지 않는다.

## 실제 앱의 핵심 검수 시나리오

- [ ] 같은 날 새로고침하면 같은 카드 순서·위치로 복원된다.
- [ ] 학습 중 수준·목표 변경이 기존 세션을 바꾸지 않는다.
- [ ] 자정 전후·시간대 변경 시 중복 세션이나 기록 소실이 없다.
- [ ] 새 단어/복습 부족 시 중복 없이 실제 수량을 안내한다.
- [ ] 영문 자판 입력을 히라가나·가타카나 후보로 변환하고 선택/Enter로 답안을 구성한다. nn·촉음·요음·장음과 미완성·잘못된 입력·IME 조합·삭제를 검수한다.
- [ ] 직접 입력 채점에서 가나 동등 비교를 지원하되 촉음·장음을 무시하지 않는다.
- [ ] 답 확인·힌트·재시도로 정답률이 부풀려지지 않는다.
- [ ] 마이크 거부·무음·네트워크 실패가 오답으로 저장되지 않는다.
- [ ] 두 번 클릭·두 탭 동시 학습에서 카드 완료가 중복 집계되지 않는다.
- [ ] 저장 실패 시 계속 저장된 것처럼 안내하지 않는다.
- [ ] 즐겨찾기 변경 후 재접속하면 동일한 목록을 볼 수 있다.
- [ ] 잘못된 백업 가져오기가 기존 기록을 지우지 않는다.
- [ ] 콘텐츠 버전 변경 중에도 기존 세션을 완료할 수 있다.
- [ ] PC Chrome/Edge, Android Chrome, iPhone Safari에서 핵심 학습 흐름을 점검한다.
- [ ] 음성 지원은 API 존재뿐 아니라 실제 일본어 인식/재생까지 확인한다.
- [ ] 키보드·200% 확대·320px 화면·모션 감소·일본어 스크린리더 표시를 확인한다.
- [ ] 원격 저장소 하위 경로에서 이미지·검색·직접 진입이 작동한다.

위 항목은 앞으로 실제 기능을 구현하면서 수행할 검수 기준이며 현재 시안에서 통과했다는 뜻이 아니다. 별도 QA 기록에는 이번 단계에서 실제 확인한 것만 적는다.
